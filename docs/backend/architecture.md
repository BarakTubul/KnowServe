# Backend architecture

**Status:** Target spec. The legacy backend in `backend/app/` (sync SQLAlchemy, JWT, Celery/Redis, Chroma) is **not migrated**. Migration starts in M0. Read this spec before any backend change.

## Purpose
The structure and conventions the target API and Worker services must follow. The stack is in `../architecture/tech-stack.md`; security rules are in `../cross-cutting/security-and-permissions.md`.

## Target requirements
| ID | Requirement | Milestone |
|---|---|---|
| ARCH-01 | Layering: router (HTTP only) → service (business logic, authorization decisions) → repository/query (SQL) → model. Routers contain no business logic and no DB access. | M0 |
| ARCH-02 | DB access uses SQLAlchemy 2.x **async** sessions with explicit transaction boundaries, and raw SQL where justified (for example the Authorized Retriever, CHAT-04). Permission filters are expressed in SQL. | M0 |
| ARCH-03 | Services return Pydantic/DTO objects or plain data, never ORM objects that outlive their session. | M0 |
| ARCH-04 | Request/response shapes are Pydantic models. The OpenAPI document generated by FastAPI is the FE/BE contract: CI compares it to the approved contract, and TS types are generated from it. Contract changes need Owner coordination (WF-03). | M0 |
| ARCH-05 | Errors map consistently to the SEC status rules (401/403/404, SEC-01 to SEC-03), use 422 for validation, and return a generic 5xx without stack traces. The error body format is part of the API contract (OPEN-14). | M0/M1 |
| ARCH-06 | Protected routers apply auth dependencies by default (deny by default). Each document-scoped route also performs the SEC-06 check. | M1 |
| ARCH-07 | Heavy AI libraries (LlamaIndex, PyMuPDF4LLM, provider clients) are imported lazily or initialized once per process, so health checks and cold starts stay cheap. | M0 |
| ARCH-09 | Logging is structured JSON with request/correlation ids, per MON-03 to MON-05. There is no `print`. | M0 |
| ARCH-10 | Two deployable services: **API** and **Worker**, each with its own image (STACK-09). Code shared by both lives in a narrowly scoped shared core, only when it has more than one real consumer (OPEN-01). | M0 |
| ARCH-11 | Schema changes go only through Alembic migrations, which are backward-compatible with the running revision (INFRA-05). Migration ownership is a shared contract (WF-03). | M0 |
| ARCH-12 | Config comes from environment variables (Secret Manager in prod, `.env` locally) through a typed settings object. `.env.example` lists every key with placeholders, and secrets are never committed. | M0 |
| ARCH-13 | Health (liveness) and readiness endpoints exist for both services. Readiness checks the DB. | M0 |
| ARCH-14 | Object storage (R2) is accessed through a thin storage interface. No public object URLs are generated for documents (PROD-07). | M2/M3 |
| ARCH-15 | Python tooling is uv (`uv.lock`), Ruff format+lint and Pyright, all blocking in CI (STACK-33, STACK-35). | M0 |

## Current implementation (LEGACY, not migrated)
- `backend/app/main.py` mounts the routers `/auth`, `/chat`, `/documents`, `/admin`, `/monitor`, `/ws` and `/health`. Auth comes from router-level JWT dependencies.
- The layering is router → controller → service → repository through a **sync** `UnitOfWork` (`core/unit_of_work.py`) on psycopg2. There is no Alembic; tables are created in `init_db`.
- Redis caching lives in `core/redis_client.py`. Celery is in `core/celery_app.py`. Chroma is in `core/chroma_client.py` and `core/vector_store.py`.
- Logging uses `print` with emoji.
- Config comes from `config.py` (pydantic-settings), with keys `DB_*`, `REDIS_URL`, `CHROMA_PATH`, `JWT_SECRET_KEY` and `OPENAI_API_KEY`. There is no `.env.example`.
- `requirements.txt` is unpinned and is missing imported packages (llama-index, openai, gdown, pytest-asyncio).
- `app/chroma_data/` and `app/static/docs/*.pdf` are committed binaries.

## Known gaps
ARCH-02, -04, -07 (partly met), -09 through -15 are not implemented. ARCH-01, -03 and -05 are partially reflected in the legacy layering and error mapping, but on the legacy stack.
