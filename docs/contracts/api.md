# API contract (M0)

Requirements: ARCH-04, ARCH-05, ARCH-13, STACK-38, FE-ARCH-01, FE-ARCH-02.

## Endpoints in M0
| Method + path | Auth | Response |
|---|---|---|
| `GET /health/live` | none | `200 {"status":"ok"}` (process is up; no dependencies checked) |
| `GET /health/ready` | none | `200 {"status":"ready"}` if the database answers `SELECT 1`; otherwise `503` with the error envelope, code `DEPENDENCY_UNAVAILABLE` |
| `GET /v1/status` | none (M0 only) | `200 {"service":"api","version":"<str>","environment":"local\|ci\|production","database":"ok"}`; `503` envelope if the database is down. Used by the frontend status page (M0-AC02). |

Product routes are all under `/v1`. M0 adds no others. There is **no public enqueue endpoint**: jobs are created in tests through `knowserve_core.jobs.enqueue_job`.

### Spike-only endpoints (M0-08)
Registered **only** when `KS_ENABLE_SPIKE_ENDPOINTS=true`; otherwise they return the normal 404 envelope and are absent from the OpenAPI baseline.
- `POST /v1/spike/cookie` sets a non-sensitive test cookie `ks_spike=1` with `Secure; HttpOnly; SameSite=Lax; Path=/; Max-Age=300` and **no `Domain` attribute** (host-only). Returns `204`.
- `GET /v1/spike/echo` returns `200 {"cookie_present": true|false}`.
- `GET /v1/spike/stream?seconds=<1..600>&interval=<0.1..10>` returns `text/event-stream` (`Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`): one `data: {"n": i, "of": total}` event per interval, then a final `event: done`. It exists only to measure proxy buffering, header forwarding and request timeouts in the deployed spike (hosting comparison); it is not the chat stream.
These carry no session semantics and are removed or left disabled before M1.

## Error envelope (OPEN-14, ARCH-05)
Every non-2xx response from the API and the Worker is JSON:
```json
{"error": {"code": "DOCUMENT_NOT_FOUND", "message": "Document not found", "request_id": "req_ab12cd34ef56ab12", "details": []}}
```
- `code`: stable UPPER_SNAKE identifier. `message`: safe to show. `request_id`: equals the `X-Request-ID` response header and the logged id. `details`: present only for 422.
- Statuses and the codes used so far: 401 `UNAUTHENTICATED`, 403 `FORBIDDEN`, 404 `NOT_FOUND`, 405 `METHOD_NOT_ALLOWED`, 409 `CONFLICT` or a specific code, 422 `VALIDATION_ERROR`, 500 `INTERNAL_ERROR` (generic, no stack trace), 503 `DEPENDENCY_UNAVAILABLE`. Feature milestones add specific codes (for example `ACTIVE_DEPARTMENT_REQUIRED`).
- Implemented once in `knowserve_core.web` (`install_web`, `AppError`); services do not hand-roll error bodies.

## Request ids
`X-Request-ID` is accepted if it matches `^[A-Za-z0-9_.-]{8,64}$`, otherwise a new `req_<16 hex>` is generated. It is always echoed on the response and stored as the correlation id for anything the request enqueues.

## CORS
Allowed origins come only from `KS_API_ALLOWED_ORIGINS` (explicit list, never `*`), with credentials allowed, exposing `X-Request-ID`. CORS is **not** a CSRF defense (AUTH-14); CSRF enforcement is M1.

## OpenAPI baseline
`docs/contracts/openapi.json` is the approved contract. It is generated by `uv run python -m knowserve_api.export_openapi > docs/contracts/openapi.json` with default settings (spike endpoints off). CI regenerates it and fails on any difference; TypeScript types are generated from it with `openapi-typescript` (M0-AC06). An intentional API change updates the file in the same commit, with Owner approval.
